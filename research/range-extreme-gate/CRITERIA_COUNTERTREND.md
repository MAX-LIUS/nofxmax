# 预登记判据 2：逆势过滤（CLUSDT 那类）

假设：`fibonacci_context.direction` 指示的结构方向与开仓方向相反时，期望更差。
定义（依 `market/fibonacci.go:57-68`，已核对源码）：
  retracement_up   = 下跌结构 → LONG  为逆势
  retracement_down = 上涨结构 → SHORT 为逆势

与判据 1 的关键区别：这里**不是**几何距离，而是方向一致性。
判据 1 失败的原因（系统本质趋势跟随，极限位置反而最强）**不适用**于本假设——
恰恰相反，如果系统靠趋势跟随赚钱，那么逆势单就应该是它最弱的一类。
所以这条假设的先验比判据 1 高。

## 主指标
同判据 1：`nret = (exit-entry)*dir/atr_price`，ATR 归一化。
另报中位数与胜率（均值易被离群单主导，已在判据 1 踩过一次）。

## 通过门槛（全部满足）
1. **效应量**：逆势 vs 顺势，中位数差 <= -0.10 ATR 且胜率差 <= -3pp。
2. **时间半分**：两半同号。
3. **样本量**：逆势组 n >= 100。
4. **分方向成立**：LONG 逆势与 SHORT 逆势**各自**同号。
   仅一边成立 = 可能是 beta（记忆里 LONG/SHORT 不对称已被证明是 beta 非 skill）。
5. **不是止损宽度的代言**：逆势组若同时止损更宽，须在控制 atr_pct 后仍成立。

## 预设结论路径
- 全过 → 实现逆势门禁（默认 audit-only，参数可配 + 开关）
- 1、2 过但 4 只单边 → 只对该方向做缩仓，不做拦截
- 效应量不过 → 否决，写入 memory 作第九条
