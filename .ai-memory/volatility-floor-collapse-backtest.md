# 波动率 floor 与档位塌陷回测 (2026-08-01)

结论先行：**两项都不要做**。floor 保持默认关闭；塌陷不需要修。
两个结论都由数据推翻了我自己先前的提议。

## 数据源与一个必须记住的坑

1663 笔已平仓（88% 覆盖），ATR 从 `decision_records.input_prompt` 逐币提取。

**门禁读的是 1h ATR,不是 15m。** 我第一次搞错了:
- `computeATR14Pct` 偏好 `IntradaySeries.ATR14` → `LongerTermContext` → `TimeframeData`
  回退(顺序 `["1h","15m","4h","30m","5m","1d"]`)。
- 但生产路径 `GetWithTimeframesExchange`(market/data.go:171-491)**从不给
  `IntradaySeries`/`LongerTermContext` 赋值**,两者恒为 nil → 必然落到回退分支
  → **1h 优先**。四个策略 `selected_timeframes` 全含 1h(含 primary=15m 的
  Claude15-chart)。
- 独立验证:`peak_pnl_pct / peak_atr_mult` 反算出的是**保护档位**冻结的 ATR。
  它与 prompt 里 1h 值吻合(中位 1.0011,98.8% 在 ±25% 内),与 15m 值是 1.97
  (差一个 √4)。**门禁与保护档位读的是不同的 ATR**,这个不对称要记住。

ATR% 分布(1h):p1=0.080 p5=0.168 p25=0.331 **p50=0.526** p75=0.789 p95=1.331。

## floor 扫描:1.1% 以下每一档都是负的

基线 1663 笔净 **−93.52**,胜率 55.3%。

| floor% | 拦截 | 占比 | 净值变化 |
|---|---|---|---|
| 0.3(我设的默认) | 19 | 1.1% | **−5.73** |
| 0.5 | 125 | 7.5% | −0.33 |
| 0.7 | 316 | 19.0% | −37.31 |
| 0.9 | 565 | 34.0% | −55.76 |
| 1.1 | 753 | 45.3% | −60.27 |
| 1.2 | 841 | 50.6% | +10.15 |
| 1.5 | 1084 | 65.2% | +99.54 |

被拦掉的单胜率**更高**(floor 0.3 时 63.2% vs 留下 55.2%)。1.2% 才转正,但已砍掉
一半仓位,且不给它"躲过最惨一单"的功劳就翻成 **−11.01**。1.3% 以上稳健且两半
时间同向,但要砍 55–86% 的单 —— 那不是过滤器,是关机。

**手续费假设被否掉。** 低 ATR 桶手续费占比确实最高(0–0.2% 是 0.40,0.2–0.4% 是
0.16,而 1.0–1.5% 只有 0.05),但那两桶**净盈利**(+0.54/+5.42,胜率 50%/62.1%)。
亏损集中在 **1.0–1.5%** 桶:428 笔 **−150.21**,那里手续费根本不是问题。
`min_eff_pct` 地板本身的必要性(0.106% 目标 < 0.12% 成本)仍成立,但那是单笔
算术,**不构成开 floor 的理由**。

## 一个有意思但不要采用的发现:1.1–1.3% 中间带

只占 10.2% 的单(170 笔),排除后 **+135.86**。通过了我设计的几乎所有稳健性检查:
15 个品种 13 个单独为负、逐一剔除任何单个品种仍 ≥+103、5 个交易员符号一致、
13 周里 10 周该带跑输**同周**其他单(说明不纯是行情代理)。

**仍然不要做**,理由是方法论的:我搜了几十个 (lo,hi) 组合再挑最好的报出来,这是
过拟合的教科书形态。96% 的亏损来自 3 周(55 笔),claude 一个交易员占
−95.73/−135.86(70%),而且**说不出这个特定区间的机制**。没有机制的参数上线就是
等着失效。真正该追的是那 428 笔 1.0–1.5% 的单除了 ATR 还有什么共性。

## 档位塌陷:问的是错的问题

各策略地板不同(**这点我先前说错了**):claude-hhhl / BN-chart+ = **0.5**,
Claude15-chart / GPT-hhhl+ = **0.3**。且 `atr_protection` 在配置**顶层**,
不在 `protection` 下。档位倍数:TP 0.9/1.3/2.5/3.0 ATR(比例 20/15/15/15),
BE 激活 1.5/3.5 ATR、偏移 0.5/1.5 ATR。

当前配置下重叠 **84/1370 = 6.1%**,四档全塌 2 笔 = 0.1%。

**关键发现:84 起全是 BE+TP 撞价,TP-TP 撞价 0 起。**

| 撞价组合 | 起数 | 例 |
|---|---|---|
| BE1,TP1 | 59 | BTCUSDT claude atr=0.5303% floor=0.5 |
| BE1,TP1,TP2 | 12 | XAUUSDT claude atr=0.3642% |
| BE1,BE2,TP1,TP2 | 11 | XAUUSDT claude atr=0.333% |
| BE1,BE2,TP1..TP4 | 2 | XAUUSDT claude atr=0.1039% |

所以它**不是收益问题**(出场价没变,P&L 回测看不到),而是 v1.17.6「一张单两个
主人」的同形态。但**三重证据表明后果已被现有代码挡住**:

1. **身份撞车不可能**:`isBreakEvenTaggedOrder` 要求 `looksLikeStopLoss`,而后者
   显式排除 `TAKE_PROFIT`/`TP` 类型 → TP 单不会被误认成 BE 单。
2. **超卖被交易所兜底**:各 venue `NativeReduceOnly: true`。真实成交验证:
   84 笔中 83 笔有平仓事件,`SUM(close_ratio_pct) > 105%` 的 **0 笔**。
3. **收益方向相反**:受影响 84 笔净 **+4.17**(均 +0.0496,胜率 59.5%),
   未受影响 1286 笔净 **−86.66**(均 −0.0674,胜率 58.2%)。
   `break_even_stop` 占比 36.9% vs 26.2% —— 同价时 BE 确实容易赢,但那是
   **在地板价锁住小赢**,不是伤害。样本小(84 笔)不宜夸大,但方向与"塌陷有害"相反。

上界计算(在决定是否付真回放成本之前先算):受影响者若"亏损单全部归零"上界
+37.68(物理不可能);若"堆叠仓位在自身 MFE 完美出场"上界 **+6.87**,对比同窗口
亏损 −88.59 = 7.8%。**天花板太低,真回放改变不了结论**,故未做。
