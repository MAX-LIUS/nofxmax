# 账户权益熔断回测（claude 利润回撤课题）

**结论（2026-07-29）：账户权益回撤熔断不应上线到 claude。** 回撤触发信号在
三个交易员上均未通过安慰剂检验，1.5-4% 区间内不存在最优值（是"不存在"，
而非"没找到"）。

## 1. 用户诉求原文要点
仓位>2 或保证金使用率达标（需考虑杠杆）时，账户权益回撤 X% 全仓熔断；
熔断后正收益达到一定比例才重新挂上熔断，否则各自仓位控制等反转或单仓止损。
后续澄清：1.5-4% 与生效涨幅"仅为举例"，均在调参范围内；熔断=权益价值冻结，
冻结点后开仓算新周期，宏观模式实现即可。

## 2. 先修引擎（3 个既有根因，commit b525a40）
1. **`realizedPnL()` 漏乘 `exitFrac`**：部分平仓在飞行中按全量记账（30% 减仓
   计为 3.33 倍）。组合权益曲线每 bar 都读它，熔断正是在该曲线触发 → 此前所有
   熔断结论都建立在被放大的权益序列上。既有测试全在完全平仓后断言，故无法发现。
2. **loader 读 `quantity` 而非 `entry_quantity`**：quantity 是实时剩余量，
   claude 557 行中 79 行为 0 → 尺寸错误且 79 仓被 `qty<=0` 静默丢弃（仅载入 478）。
3. **`.gitignore` 的 `backtest` 无前导斜杠**：在每层目录生效，静默排除整个
   `trader/backtest/` 源码目录，新增文件提交即丢失。已改 `/backtest`。

## 3. 两代模型
- **重开仓模型（已弃用）**：必须虚构"同一仓位 N bar 后在价格 P 重建"这一无
  证据反事实，虚构敞口复利放大 → 曾造成 +98 次开火的严重非单调。
- **权益冻结模型（采用，`L3Cycle*`）**：开火时全仓按当前 mark 平掉——不毁灭
  价值而是**结晶**价值，账户曲线穿过开火点连续。结晶后的已实现权益成为新周期
  基线（回撤峰值重置），冻结点后交易员**真实**开的仓构成下一周期。只决定在何
  处**截断真实仓位**，从不创造敞口 → 各参数下开仓样本完全一致，阈值才可比。
  - 残留假设（须明说）：交易员冻结后的开仓，是在"账本未被清空"的世界里做的
    决策。这是 overlay 研究的标准外生假设，远小于虚构重开仓。

## 4. 安慰剂对照 —— 本课题的关键
**为什么必须做**：冻结模型下开火 = 永久提前离场；三个交易员基准全为亏损，
故任意时点截断都倾向改善盈亏。「熔断优于基准」不是证据，只说明少持仓有利。
对照组 = 同机制/同费率/同 arm 门槛，仅把回撤触发换成种子化抛硬币，在**相同
开火次数**下比分位。

**首版结论是错的，教训记牢**：首版安慰剂全部跑在 arm=0，得出"54/90 战胜硬币"。
arm=0 时 100% 时间武装、开火均匀分布；arm=12% 只在盈利后约 3% 的时间武装。
两者开火**次数**相同但**时机分布**完全不同 → 把 arm 门槛的止盈效应记到了回撤
触发头上。**按 arm 配对后**（`L3CycleGrid` 的安慰剂行现在同步扫 arm 轴）：

| 交易员 | 基准 PnL | 战胜硬币 |
|---|---|---|
| claude | -126.70 (-54.05%) | **2 / 98** |
| GPT | -27.20 (-44.07%) | **2 / 98** |
| Claude-R | -41.42 (-103.24%) | **10 / 81** |

98 次检验在 p<0.05 下偶然期望约 5 个 → 与噪声同阶。另一佐证：`drop%` 几乎
不影响结果（arm=12 时 1% 与 20% 同为 -52），做功的是 `arm%` 而非回撤阈值。

## 5. 单调性（回应"1.9% 出现 4 次而 2.0% 出现 39 次不可能"）
- 新增 `-cyclemeasure` 探针：只测量不动仓位，移除反馈闭环 → 计数**必须**单调。
- 三个交易员真实数据全部 `monotonicity OK`；合成用例 10,9,8,7,6,5,4,4,3,3,2,1。
- 据此确认**触发测量正确**；实盘扫描残留非单调（claude +6 / GPT +24 / CR +33）
  来自"开火重置回撤峰值"的模型内在反馈，非引擎缺陷。
- 同时修掉检查器自身污染：此前把安慰剂行（`dd=999%` 哨兵、仅种子不同）纳入
  分组比较，把种子间离散度误报为 +76 次违规。

## 6. 为什么 1.5-4% 先天不可能
raw 权益回撤% ≈ 杠杆 × 价格波动%。claude 有效杠杆约 3.7x → 1.5% 权益回撤
仅对应约 0.4% 价格波动，落在 tick 噪声内，比任何止损都紧。这也是代码里既有
结论"raw equity% 受杠杆污染、10x 下 0.5% 噪声就开火"的由来。

## 7. 更深的问题：回放保真度
claude 63% 的平仓（350 仓，-42.82）来自本引擎未实现的机制：native_trailing、
AI 主动平仓(close_short/close_long)、max_hold、giveback_guard_breadth、
sync_absent_from_exchange。实际 vs 建模：claude -36.67/-72.83、CR -27.82/-62.80、
GPT -0.44/-45.17(103x)。故新增 `FaithfulExits`（按真实 ExitTime/ExitPrice 回放，
关掉所有建模保护层），claude 收敛到 -41.90 vs 真实 -36.67。**所有熔断结论都在
faithful 模式 + 手续费开启下得出**（手续费必开：熔断不产生 alpha，唯一成本是
换手，零费率下多开火免费，优化器会疯狂开火）。

## 8. 工具与坑
- `cmd/gbsim`：`-acct -cycle -faithful -tf 1h -capital N -nomlev 10 -feerate 0.05`；
  `-cyclemeasure` 为引擎探针。K 线来自 OKX API 逐仓拉取，不是 DB。
- `L3Fires` 是**逐仓削减次数**不是开火次数（一次 4 仓全平记 4）。频率一律用
  `L3Events` / `L3Cycles`。
- **BN 无法回放**：Binance 返回 HTTP 451 地理封锁，生产靠 `BINANCE_PROXY_URL`，
  但 gbsim 从未注册代理钩子（只有 main.go 注册）。未覆盖。
- 4h 与 1h 结论完全冲突（基准 -55% vs -31%）；claude 持仓中位数 7.92h、32% 在
  4h 内平仓 → 4h 对这本账本过粗，用 1h。

# 追加（2026-07-29 第二轮）：0.1% 精扫 + 样本外切分，结论升级

## 9. 三处修正
1. **回撤%按原始权益、不除杠杆**（用户澄清）。核对确认引擎本就如此：
   `curEquity = StartCapital + preRealized + preUnreal`，
   `ddPct = (peak-cur)/peak*100`，148→146.52 即 1%。杠杆只用在保证金使用率门槛。
   已加 `TestDrawdownIsOnRawEquityNotLeverageAdjusted` 钉死：1.08% 原始回撤下
   dd=1.0% 必开火、dd=1.2% 必不开火（若杠杆渗入则两者都不开火，测试立即失败）。
2. **0.1% 步进精扫** `L3CycleFineGrid`：dd 0.1-6.0%(步进 0.1)、arm 0-10%(步进 0.5)，
   1260 格。**此前粗网格 arm 只有 {0,1,2,3,5,8,12}，根本没跑过 arm=4%** ——
   争议配置本身从未被测试。教训：用漏掉争议点的网格下结论是无效的。
3. **BN 经代理接入**：`proxyhook.Register()` + `-env/-binance`，150/151 仓回放成功
   （此前 0 仓）。只提取 `BINANCE_PROXY_URL` 单键，不用 `godotenv.Load`（K 线是
   公开数据，没理由把实盘密钥载入回测进程）。

## 10. 决定性证据：参数不可提前选择（时序训练/测试切分，正反双向）
切分按**时间**而非随机——同时开仓的仓位共享同一段行情，随机切分会泄漏。

| 交易员 | 正向留存 | 反向留存 |
|---|---|---|
| claude | **−23%** | 21% |
| GPT | 160% | **−99%** |
| Claude-R | 6% | 249% |
| BN | 0% | **−217%** |

claude 正向选出 dd=3.2/arm=2.5 训练 +97.53 → 样本外 **−22.64**；反向选出
dd=1.9/arm=0 训练 +65.04 → 样本外 +13.79。两个方向**互为对方的"事后最优"**。
争议配置 dd=2/arm=4：正向 +96.04→**−16.86**，反向 −16.86→+96.04；其邻域
(arm 3-5%, dd 1.5-2.5%) 55 格正向 **0/55** 为正、反向 **55/55** 为正。
**符号随切分方向翻转 → 测到的是两段行情的差异，不是可学习的参数。**

## 11. 对照(4)「直接减仓」——这才是正确做法
不用熔断、无参数可拟合、无额外换手与手续费。claude：

| 仓位 | 训练 edge | 样本外 edge |
|---|---|---|
| 75% | +20.28 | +11.39 |
| 50% | +40.57 | +22.78 |
| 25% | +60.85 | +34.17 |
| 10% | +73.02 | +41.01 |

**训练与样本外同时改善且单调**，与熔断的符号翻转形成鲜明对比。
→ 用户判断「在亏损账本上降低敞口是正期望」**完全正确**，但收益来自
**少持仓**，与回撤阈值无关。熔断是用可过拟合、需换手的方式，去买减仓一行
代码就能买到的东西。

## 12. 为什么「正期望」直觉与「不如掷硬币」并不矛盾（要能复述）
配对后的安慰剂与真实规则**同样**等到 +arm% 才武装、同样在盈利后平仓、同样付
手续费，唯一区别是出场时机。真实规则的出场价**恒为「峰值−dd%」**；安慰剂在
武装后随机某刻出场，有时更早（更优）有时更晚（更差），**均值与前者相当**。
所以 dd 这个数字不携带任何关于未来的信息，它只是在武装后的权益分布上挑了一个
固定分位点。而「优于基准」为真是因为在亏损账本上任意截断都倾向改善盈亏——
这两句话同时成立，回答的不是同一个问题。

# 追加（第三轮）：改用真实权益曲线，找到熔断失效的真正原因

## 13. 之前一直在答错的对象
用户问的是「历史 pnl 曲线」，而系统里存着真实记录 **`trader_equity_snapshots`**
（claude 3281 条，6/19→8/2）。前两轮都在分析**回放重建**的曲线，那条曲线还带着
63% 未实现机制的缺口。新增 `-realcurve` 直接读真实曲线、`-ddstat` 做事件分解。

事件计数规则：新 episode **只在创新高时开始**，一段未恢复下跌中的多次探底算
**同一个** episode。每次探底单独计数会放大「2% 回撤有多频繁」，方向上美化熔断。

真实曲线（claude）：起 234.85 → 峰 **299.61** → 现 **146.52**，22 个 episode。
触及 2% 共 **3 次**（其中 **2 次自行恢复**），触及 10% 共 1 次。

## 14. 决定性发现：这条曲线上「距峰回撤」是个一次性开关
**峰值 299.61 出现在 6/23，即 44 天里的第 4 天；之后 2969/3281（90%）样本都在
峰下，且再没回去过。**

所以任何阈值的熔断都在第 4~5 天开火一次，然后**永久处于"该开火"状态**。它不是
偶发保护，是第 5 天拨下就再没抬起的开关。这一条同时解释了：
- 为什么阈值选择无意义（全都在同一个状态里）；
- 为什么训练/测试切分会翻转符号（取决于哪半段含那个转折）。

## 15. 分桶前瞻收益：2-4% 一带方向相反
claude 24h 前瞻收益按回撤深度分桶：

| 深度桶 | n | 24h 前瞻 |
|---|---|---|
| 0–0.5% | 101 | **+4.00%** |
| 0.5–1% | 28 | +3.20% |
| 1–2% | 52 | +1.15% |
| **2–3%** | 74 | **+2.61%** |
| 3–5% | 83 | +1.92% |
| 5–8% | 66 | −1.60% |
| **>8%** | **2805(87%)** | −1.06% |

**在争议的 2–4% 一带前瞻收益为正 → 此处开火是卖在反弹前。** 只有 >5% 转负。
而 >8% 桶独占 87% 样本，先前"回撤中前瞻更差"的结论**完全由该桶主导**，实质是
「这个账户 90% 时间深水且全程负漂移」，不是「距峰回撤有预测力」。

## 16. 必须记住的自纠：我自己的工具曾伪造出 +124 支持熔断
`simulateFreeze` 初版只在**原始曲线创历史新高**时解冻。而一条从 299 跌到 146
再未恢复的曲线**永不创新高** → 一次冻结后永久不参与。它建模的是「在高点附近
永久停止交易」，对暴跌曲线自然大赢，曾报出 **+124.78** 的假收益（每个阈值都
"BETTER than holding"）。用 `{80,90,100,95,90,80,70,60,50}` 探针确认：一次冻结
后权益停在 95，永不解冻。
**教训：在权益曲线上做回撤熔断研究必须显式声明重入规则，否则测到的是市场择时
而不是熔断。** 已改为显式重入（冻结 N 样本后按新周期重挂），并增印 `never` 列
专门暴露"收益有多少来自停止参与而非回撤触发"——该列 233/235/263 也全赢 hold
（146.52），即停手本身就拿到大部分收益。

## 17. 真实曲线上的安慰剂（200 种子/行，匹配冻结次数）
claude 80–98 分位、Claude-R 96–100、BN 66–96、GPT 20–87。三个交易员确实高于
随机中位数——但结合 §15，来源是「深水期(>8%)前瞻为负」而非「距峰 2% 有信息」，
且安慰剂分布极宽（claude 2% 档 90.97–410.95），真实值 271 仍在随机上界之内。

## 18. 最终结论（三轮一致）
用户判断「降低敞口是正期望」**正确**，且在真实曲线上「深水期减仓」确实有效
（>5% 桶前瞻为负）。但**「距峰 2–4% 熔断」不成立**：那一带前瞻为正。真正可执行
的是 §11 的**直接减仓**（训练/样本外双侧同时改善且单调），以及必要时按「深水
程度」而非「距峰回撤」调整敞口。

# 追加（第四轮）：按「稳定爬楼梯」目标给出最佳参数

## 19. 之前用错了目标函数
前三轮都按 **PnL** 排名，而用户要的是「稳定爬楼梯」= **路径形状**目标。一条翻倍
再腰斩的曲线可以在最终 PnL 上胜过稳步上行的曲线，却远难持有。改用：
- **Ulcer Index** = 全样本回撤均方根，同时惩罚回撤的**深度与持续时间**
  （maxDD 无法区分「跌 10% 一小时」和「水下 10% 两周」）
- **Martin 比率** = 收益 / Ulcer，作为排名指标
- **timeAtHigh** = 距峰 0.5% 内的样本占比（字面意义的「站在台阶上」）

新增 `-stair`：涨幅{0..10%} × 回撤{0.1..6.0% 步进 0.1%} × 重入延迟{6,18,72,216,
504,1008 样本}，4320 格，时序前后半切分。

## 20. 最公允答案（maximin：按较差那半段排名，且要求 inMkt>=60%）

| 交易员 | 涨幅挂上 | 回撤开火 | 重入延迟 | 全程 return | maxDD |
|---|---|---|---|---|---|
| **claude** | **+5.0%** | **6.0%** | **3 天** | −37.68% → **+19.64%** | 53.69% → 30.12% |
| GPT | +2.0% | 3.5% | 1 天 | −40.08% → −11.83% | 50.91% → 43.45% |
| Claude-R | +2.5% | 0.1% | 7 天 | −78.85% → −43.68% | 84.59% → 53.24% |
| BN | +0.5% | 0.6% | 1 天 | +38.34% → +84.45% | 48.02% → 20.75% |

**四者无任何共同值 → 参数不可跨交易员迁移。** 注意 claude 的答案是 **6%**，
不在用户提的 2–4% 区间内。

## 21. 但这是孤立尖峰，不是可用设定（关键）
固定 arm=5/delay=216 变动回撤：1%→−1.569、2%→−1.430、3%→−1.433、4%→−1.177、
5%→−1.289、**6%→+0.281（唯一为正）**
固定 arm=5/回撤=6% 变动延迟：6→−1.194、18→−1.129、72→−1.367、**216→+0.281
（唯一为正）**、504→−1.537、1008→−1.827

**两个轴上每一个邻居都是负的。** 4320 格中两半段同时为正的仅 **251 格(5.8%)**。

另一个确证：首版网格延迟上限为 216 时「最优」是 1.5/0.1/216（样本外 +8.27%）；
**仅把延迟上限扩到 504/1008，最优就搬家到 5.0/1.2/504（样本外 −10.66%）**。
扩一格网格就换答案 = 拟合噪声。

## 22. 必须与平滑度指标并列打印 TimeInMktPct
冻结区间完全水平，且水平样本会被计入「处于高位」→ **空仓本身就会机械地改善
Ulcer 指标，不需要任何技巧**。不打印该列，优化器必然收敛到「停止交易」并伪装成
调好的熔断（claude 首版最优 inMkt 仅 **21.5%**，即 78.5% 时间不在场）。
已由 `TestFrozenStretchesInflateSmoothness` 断言该效应存在。

## 23. 又一个自纠：度量在自己的最优点上是错的
`Ulcer=0`（完美楼梯）时按 `if UlcerIndex > 1e-9` 守卫会得 `Martin=0`，**反而排在
boom-bust(0.31) 之后** —— 理想情况得最低分。测试
`TestPerfectStaircaseScoresBetterThanBoomBust` 抓到，改为正收益零回撤取 `+Inf`。
真实曲线无零 Ulcer，故先前扫描结果不受影响，但度量本身曾是错的。
