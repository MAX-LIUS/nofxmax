# 账户权益熔断回测（claude 利润回撤课题）

**结论（2026-07-29）：账户权益回撤熔断不应上线到 claude。** 回撤触发信号在
三个交易员上均未通过安慰剂检验，1.5-4% 区间内不存在最优值（是"不存在"，
而非"没找到"）。

## 1. 用户诉求原文要点
仓位>2 或保证金使用率达标（需考虑杠杆）时，账户权益回撤 X% 全仓熔断；
熔断后正收益达到一定比例才重新挂上熔断，否则各自仓位控制等反转或单仓止损。
后续澄清：1.5-4% 与生效涨幅"仅为举例"，均在调参范围内；熔断=权益价值冻结，
冻结点后开仓算新周期，宏观模式实现即可。

## 2. 先修引擎（3 个既有根因，commit b525a40）
1. **`realizedPnL()` 漏乘 `exitFrac`**：部分平仓在飞行中按全量记账（30% 减仓
   计为 3.33 倍）。组合权益曲线每 bar 都读它，熔断正是在该曲线触发 → 此前所有
   熔断结论都建立在被放大的权益序列上。既有测试全在完全平仓后断言，故无法发现。
2. **loader 读 `quantity` 而非 `entry_quantity`**：quantity 是实时剩余量，
   claude 557 行中 79 行为 0 → 尺寸错误且 79 仓被 `qty<=0` 静默丢弃（仅载入 478）。
3. **`.gitignore` 的 `backtest` 无前导斜杠**：在每层目录生效，静默排除整个
   `trader/backtest/` 源码目录，新增文件提交即丢失。已改 `/backtest`。

## 3. 两代模型
- **重开仓模型（已弃用）**：必须虚构"同一仓位 N bar 后在价格 P 重建"这一无
  证据反事实，虚构敞口复利放大 → 曾造成 +98 次开火的严重非单调。
- **权益冻结模型（采用，`L3Cycle*`）**：开火时全仓按当前 mark 平掉——不毁灭
  价值而是**结晶**价值，账户曲线穿过开火点连续。结晶后的已实现权益成为新周期
  基线（回撤峰值重置），冻结点后交易员**真实**开的仓构成下一周期。只决定在何
  处**截断真实仓位**，从不创造敞口 → 各参数下开仓样本完全一致，阈值才可比。
  - 残留假设（须明说）：交易员冻结后的开仓，是在"账本未被清空"的世界里做的
    决策。这是 overlay 研究的标准外生假设，远小于虚构重开仓。

## 4. 安慰剂对照 —— 本课题的关键
**为什么必须做**：冻结模型下开火 = 永久提前离场；三个交易员基准全为亏损，
故任意时点截断都倾向改善盈亏。「熔断优于基准」不是证据，只说明少持仓有利。
对照组 = 同机制/同费率/同 arm 门槛，仅把回撤触发换成种子化抛硬币，在**相同
开火次数**下比分位。

**首版结论是错的，教训记牢**：首版安慰剂全部跑在 arm=0，得出"54/90 战胜硬币"。
arm=0 时 100% 时间武装、开火均匀分布；arm=12% 只在盈利后约 3% 的时间武装。
两者开火**次数**相同但**时机分布**完全不同 → 把 arm 门槛的止盈效应记到了回撤
触发头上。**按 arm 配对后**（`L3CycleGrid` 的安慰剂行现在同步扫 arm 轴）：

| 交易员 | 基准 PnL | 战胜硬币 |
|---|---|---|
| claude | -126.70 (-54.05%) | **2 / 98** |
| GPT | -27.20 (-44.07%) | **2 / 98** |
| Claude-R | -41.42 (-103.24%) | **10 / 81** |

98 次检验在 p<0.05 下偶然期望约 5 个 → 与噪声同阶。另一佐证：`drop%` 几乎
不影响结果（arm=12 时 1% 与 20% 同为 -52），做功的是 `arm%` 而非回撤阈值。

## 5. 单调性（回应"1.9% 出现 4 次而 2.0% 出现 39 次不可能"）
- 新增 `-cyclemeasure` 探针：只测量不动仓位，移除反馈闭环 → 计数**必须**单调。
- 三个交易员真实数据全部 `monotonicity OK`；合成用例 10,9,8,7,6,5,4,4,3,3,2,1。
- 据此确认**触发测量正确**；实盘扫描残留非单调（claude +6 / GPT +24 / CR +33）
  来自"开火重置回撤峰值"的模型内在反馈，非引擎缺陷。
- 同时修掉检查器自身污染：此前把安慰剂行（`dd=999%` 哨兵、仅种子不同）纳入
  分组比较，把种子间离散度误报为 +76 次违规。

## 6. 为什么 1.5-4% 先天不可能
raw 权益回撤% ≈ 杠杆 × 价格波动%。claude 有效杠杆约 3.7x → 1.5% 权益回撤
仅对应约 0.4% 价格波动，落在 tick 噪声内，比任何止损都紧。这也是代码里既有
结论"raw equity% 受杠杆污染、10x 下 0.5% 噪声就开火"的由来。

## 7. 更深的问题：回放保真度
claude 63% 的平仓（350 仓，-42.82）来自本引擎未实现的机制：native_trailing、
AI 主动平仓(close_short/close_long)、max_hold、giveback_guard_breadth、
sync_absent_from_exchange。实际 vs 建模：claude -36.67/-72.83、CR -27.82/-62.80、
GPT -0.44/-45.17(103x)。故新增 `FaithfulExits`（按真实 ExitTime/ExitPrice 回放，
关掉所有建模保护层），claude 收敛到 -41.90 vs 真实 -36.67。**所有熔断结论都在
faithful 模式 + 手续费开启下得出**（手续费必开：熔断不产生 alpha，唯一成本是
换手，零费率下多开火免费，优化器会疯狂开火）。

## 8. 工具与坑
- `cmd/gbsim`：`-acct -cycle -faithful -tf 1h -capital N -nomlev 10 -feerate 0.05`；
  `-cyclemeasure` 为引擎探针。K 线来自 OKX API 逐仓拉取，不是 DB。
- `L3Fires` 是**逐仓削减次数**不是开火次数（一次 4 仓全平记 4）。频率一律用
  `L3Events` / `L3Cycles`。
- **BN 无法回放**：Binance 返回 HTTP 451 地理封锁，生产靠 `BINANCE_PROXY_URL`，
  但 gbsim 从未注册代理钩子（只有 main.go 注册）。未覆盖。
- 4h 与 1h 结论完全冲突（基准 -55% vs -31%）；claude 持仓中位数 7.92h、32% 在
  4h 内平仓 → 4h 对这本账本过粗，用 1h。
