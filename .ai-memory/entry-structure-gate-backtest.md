## 15m 专项（Claude-R，2026-08-01）

口径：369 笔入场，中性 6h 持有，基线均值 **-0.071%**、胜率 49.1%，41.2 天内 8.96 笔/天。
harness `trader/gate15m_sweep_manual_test.go`（`GATE15M=1` 守卫，已提交 `5035861`）。

### ⚠️ 先记两个把结论推翻过的错误

1. **harness 窗口必须等于线上 120 根**。原先传完整历史，而 `buildShadowGateCtx` 只取
   `market.GetKlines(...,120)`。`chartSwingAlign` 是比率，分母随序列长度增长，长序列被大数定律
   压回 0.5 → 观测 align 上限只有 0.535，于是我曾断言「`align_min=0.55` 恒不通过」。
   那是 harness 假象。修正后 max=0.788、线上放行率 19%。常量 `gate15mLiveWindow=120`。
2. **`chartTrendGate` 返回 `block` 不是 `allow`**（`chart_trend_gate.go:107`）。我的 ground-truth
   判据一度取反，得 39%（=61% 的补集）。放行必须写 `!block`。

### chart_trend：100 格全负，不上

网格 100 格**全部负增量**，最好的格 -0.015，而线上配置 -0.197。根因是 `dirSlope>0` 这一项，
单独就 **-0.238（t=-2.28）**。Claude-R 的 15m 入场是**均值回归型**，短窗口趋势滤波
砍掉的正是它的盈利尾部。另测 11 条 shadow 规则全部 ≤ 基线。

### HH/HL：最优 lb=4 / n=3 / pct=0

参数精度的正确问法不是小数步长（lb/n 是整数），而是**相邻格点是否变号**：
- **`n=2`（部署默认值）在 15m 上无效** —— 与 4H/1H 上的推荐值相反。
- `n=3` 是唯一稳定区（lb=3..6 连续为正）。
- `n=4` 在 lb=5 处变号 → 过拟合。
- **`lb=4/n=3` 是唯一在 3 折全为正、且每折都跑赢该折基线的格点。**

**但必须同记反面**：没有任何格点达到显著性；而 `INVERTED lb=3/n=3` 拿到 t=+1.56，
比任何正向配置都高。这就是它只上 **audit_only** 而非 enforce 的原因。

### 2+3 不能同时 enforce

方案 3 放行集有 **64% 落在方案 2 放行集内**（Jaccard 0.16）。叠加只买到约 18 笔独立交易，
却把吞吐砍到 0.78 笔/天（**-91%**），每折 n 只剩 6/13/13。
落地：**方案 2 enforce，方案 3 audit_only。**

### `adx_weak` 硬编码 period=14 让最优组合无法表达

ADX(14) 在 15m 上各阈值全部平到有害（>=20 → -0.072，>=25 → -0.064，>=30 → -0.120，
基线 -0.071），**ADX(10)>=30 是唯一有效变体**。故新增 `RegimeGateParams.ADXPeriod`
（`store/strategy.go`，默认 14 保持既有行为不变）。同时给 `chart_trend` 暴露 `lookback`。

### harness 保真度上界 71%，不是 100%

已开仓样本理论上应 100% 通过线上闸门，但 K 线重算在最佳 offset 下只到 **70.7%**。
成因部分是错位一根 K（成交时刻 vs 决策时刻）；约 12 笔仍无法解释；交易所口径不一致已排除。
**因此本节所有 sweep 数字只能作相对排序用，不能当绝对期望值。**

## ⚠️ 部署当天发现并修复的窗口缺陷（比参数选择更要紧）

闸门原先读决策上下文的 K 线，而**那份数据是按 `indicators.klines.primary_count`
为 AI prompt 裁剪过的**——两件不相干的事被耦合：prompt 该多长，和闸门需要多长历史。

线上实测 `bars=21`（GPT-ct50 `primary_count=22`，去掉未收盘的那根）。按线上真实窗口
截断重跑回测：

| 窗口 | 放行率 | 增量 | p |
|---|---|---|---|
| 全部历史（回测原口径） | 33.6% | +0.263 | 0.0004 |
| 29 根（claude-ct30, primary_count=30） | 23.7% | +0.309 | 0.0002 |
| **21 根（GPT-ct50, primary_count=22）** | **7.7%** | **+0.160** | **0.1522 ❌** |
| 40 根 | 32.6% | +0.276 | 0.0004 |
| 60 根 | 33.5% | +0.263 | 0.0010 |

21 根窗口下 **92.3% 的入场是因为凑不齐 n=2 高 + n=2 低而被拦**，即拦在
「结构**看不见**」而不是「结构**不存在**」——纯数据饥饿假象，且收益增量已不显著。

**修复**：新增 `structuralBars()`，上下文不足 `structuralMinBars=30` 根时自取 120 根
（`market.GetKlines`，60s `sync.Map` 缓存，键 `symbol|tf|exchange`）。先例是
`shadow_gate.go:143` 的同类注释（"PrimaryCount is far too short"）。

两条硬约束：
1. **取数失败必须弃权放行，绝不能当作拦截**——这在执行路径上，取不到数不能变成交易决策。
2. **不照搬 shadow gate 的「取最长序列」兜底**：那会跨周期混用 15m 数据，而结构效应
   在 15m 上是**反向**的。必须锁定 primary timeframe。

`structuralMinBars=30` 不是「摆动点存在所需的算术下限」（那是 `2*lb+2=8`），
而是**验证覆盖下限**：低于它就是在对回测从未覆盖的窗口执行拦截。
8~29 根这段实测只有 15 笔（0.5%），放行 1 笔，样本上无所谓，但语义上必须堵。

回归测试 `TestStructuralGate_ThinContextAbstainsInsteadOfBlocking` 复现该缺陷：
同一笔逆势 LONG，全窗口拦截、21 根窗口弃权。

## ⚠️ 先读这一节：结论按参数区分，且我曾双向漂移过

**结论**：`pct=0`（纯方向判据，距离参数不参与）**成立**，有真样本外证据；
`pct=0.05` 这类小数级调参格点**不该用**——它比 `pct=0` 好的那一点（7 月真实 PnL
+62.97 vs +62.85，121 笔）毫无意义，却引入「参数是调出来的」这个真实弱点。
**推荐 lb=3 / n=2 / pct=0。**

早期对比只在**已开仓单**内部切分，而已开仓单**全部已通过既有闸门**，
回答不了「能否单独使用」。正确做法见「对照组实验」一节。

### 我的双向漂移（教训比结论更值得记）
先是**过度乐观**：把 6 天窗口（占历史 4.8%）当成结论，且口径改了五次仍保留结论。
然后在同一会话末尾**过度悲观**，把整个结论否掉，那次的四条反对意见有三条是错的：
- **「残余缺陷不可界定」→ 错**。那 119 笔缺陷类拦截（`stop_inside_invalidation` 等）
  **入场价全部为空、从来没进过严格样本**；剔与不剔，三个格点数字**完全相同**。
  我在给一个**对结果零影响**的操作写反对意见。65% 虚增发生在早期用「最后一根 K 线
  收盘价」回填入场价的**废弃版本**上。
- **「没有任何样本外证据」→ 错**。时间切分那轮就是样本外，p=0.0012。
- **「频率降 85% 是机制本身（样本小→误差棒宽→均值好看）」→ 被 n=2 打掉**：
  11.5 笔/天只砍一半频率，样本外增量仍 +0.272。
- 唯一站得住的是「多重比较」和「真实 PnL 非样本外」，但它们**只适用于小数级扫参**，
  对 `pct=0` 不适用（单一假设，无格点搜索）。

**教训：发现自己有过度乐观漂移后，纠正时必须逐条验证每个反对意见是否成立，
否则会用同样不严谨的方式漂到另一侧。「已剔除某类缺陷」这种操作，
必须先验证它是否真的改变了样本。**

## 对照组实验（回答「单独用 vs 配合用」的唯一有效口径）
- **对照组来源**：日志里的 `🚫 Entry gate blocked` 共 3752 条（18 天，21 币），
  其中 **1144 条日志带入场价**；`execution_log` 只有执行阶段失败(195 条)，DB 里**没有**闸门拦截记录。
- **重要边界**：带入场价的 1144 条**全部来自 `structural_fit` 阶段**。所以
  「过了 market_state」是全样本的共同前提 → **market_state 的贡献无法评估**，
  能评估的只有 structural_fit + confidence_risk。
- **公平性设计**：已开仓单有真实 PnL、被拦单没有，二者不可直接比。故**两组都用同一中性规则**
  重新模拟（持有 6h、不设止损止盈、无主动管理）。代价：模拟收益不能预测实盘绝对收益，
  只能做闸门间相对比较；盲区是**看不到保护方案缺陷**。
- **必须剔除的缺陷类拦截**：`stop_inside_invalidation` / `fallback_inside_invalidation` /
  `target_before_first_target`（119 条）。它们是「止损放在失效位内侧」这类保护方案缺陷，
  无止损模拟看不到 → 曾把某次分歧集收益虚增约 **65%**（30 笔里 27 笔是这一类）。
- **入场价重建偏差**：被拦单若用「最后一根 K 线收盘价」回填，会系统性高估闸门
  （+1.548% → 只用日志给出的价格后 +0.744%，胜率 63.8%→57.5%）。**只用日志价格。**

### 单独 vs 串联（严格样本 n=2957 = 已开仓 1839 + 被拦 1118，持有 6h）
| 配置 | n | 胜率 | 均值% |
|---|---|---|---|
| 无闸门基线 | 2957 | 48.1% | -0.034 |
| 仅既有闸门（现状放行集） | 1839 | 49.2% | -0.040 |

  在本实验里**没有对照，未被证伪**，拆它是无证据的破坏性改动。

## 参数精调（0.05 步长，选参标准不是「均值最大」）
> 这一节保留作记录。**结论是它选出的 `pct=0.05` 不该用**——见开头。
> 小数级扫参在约 50 个格点上跑六项筛查，胜出格点是被筛查**选出来**的，
> 它的 p 值不再是 p 值。而 `pct=0` 不经过这个过程。
筛查标准全部通过才算合格：三折前向滚动增量全正 / 三个月增量全正 / 多空双向为正 /
剔除最大贡献币后仍为正 / 频率≥2 笔每天 / 置换检验 p<0.05 / 4 个 trader 全部改善。
- **lb=3 是决定性的**：lb=2 是噪声（最好格点 p=0.08，三折互相矛盾），lb=4 偏弱；
  lb=3 从 pct 0 到 0.35 每个格点都显著。
- **最终参数 lb=3 / n=3 / pct=0.05**：n=284、3.29 笔/天、胜率 52.5%、均值 +0.323%、p=0.0080，
  且是唯一「4/4 trader 全改善 + 均值最高」的格点。
- 高 pct 均值更高（0.6 达 +0.923）但**过不了筛查**：月度增量转负、收益集中到单个 trader。
- n=2 换频率：8.34 笔/天但边际减半（+0.233），7 月真实 PnL 只有 +34.69 vs +62.97。

### 真实 realized_pnl 独立复核（7 月，离场机制一致）
中性模拟看不到止损/止盈/AI 管理，故用真实 PnL 再验一遍：
**全部 876 笔已开仓单合计 -78.16**，而闸门会放行的 **121 笔合计 +62.97、胜率 69.4%、p=0.0084**。
与中性模拟同向 → 边际不是模拟口径造出来的。

### 仍未消除的疑点
1. **TON 一个币贡献 35~66% 的收益**（随格点变化）。剔除后仍为正（+0.122 vs 基线 -0.034）但边际显著缩小。
2. **最优参数随窗口漂移**（这个问题贯穿整个研究，从未解决）。
3. **market_state 无法评估**（对照组全部已通过它）。
4. **开仓频率从约 21 笔/天降到约 3.3 笔/天（-85%）**。这是真实代价，不是统计噪声。
5. Claude-R(02273139) 在多数参数下为负；只有 pct≤0.05 时它才转正（+0.123）。

## 关键数据源发现（推翻旧记录，后续回测都该用）
- **`decision_records.timestamp` 是可用的**：24201 条不同值，跨 `2026-05-05 18:47` → `07-30 07:33`。
  先前会话记录的「timestamp 全是 2 / 不可用」是**错的**，误判来源不明（`created_at` 同样可用，text 格式）。
- **全部 24201 条 `input_prompt` 都内嵌 OHLC 表**（不只最近几天）。格式：
  `### N. SYMBOLUSDT` → `=== {5M|15M|1H|4H} Timeframe (oldest → latest) ===` → `MM-DD HH:MM O H L C V`。
  bar key 无年份，跨月需从该记录 timestamp 取年份补齐。
- 提取产出：**50 币种 / 182 条序列**（ETH 1H 2061 根、15M 7940 根，跨 05-04 → 07-30）。
  Binance API 地理封锁、DB 无 kline 表，所以这是唯一 K 线来源；**不必再局限于最近几天**。
- `trader_positions` 时间字段是**毫秒时间戳整数**，不是 SQLite 时间串 →
  必须 `datetime(entry_time/1000,'unixepoch')`，直接 `datetime(entry_time)` 全返回 NULL（曾据此误判「无记录」）。
- 提取脚本：`$CLAUDE_JOB_DIR/tmp/extract_hist.py`（流式，24201 条约 6 分钟），
  回测引擎 `bt_hist.py`（`closed_before` 用二分，无未来函数）。均为会话级、非持久。

## 闸门定义
- **闸门1**：主周期(1H，5 策略中 4 个的 primary)分形摆动序列 HH+HL / LH+LL 方向须与开仓方向一致。
  参数 `lb`(分形半宽) / `n`(取最近 n 组高低点)。
- **闸门2**：开仓方向前方最近**真实**摆动阻挡位距离 ≥ 阈值(0.5%)。
- **闸门5**（用户记忆中「必须的」多周期一致）：严格三周期全同向 → **全样本 0 笔通过，不可用**；
  宽松版与闸门1 重叠 34/36，因 4H 在闸门1 通过样本里 32/36 是「无结构」（4H 有 52-61 根，非数据不足，是真的少有干净 HH/HL）。

  胜率 40.8%→52.3%→63.4% 而盈亏 -18.45→-33.67→-77.91。并成一个样本回测等于拿不同系统对比。
- 7 月内部再切两半：通过组两半皆正(+43.07 / +20.79)，拦截组两半皆负。
- 邻域是**连续高原**：lb∈{2..5} × n∈{2,3,4} **12/12 均值优势为正**(+0.112~+0.592)，最强 lb=3~5；
  `minbars` 20→80 无影响(+63.86→+63.49)。**但格点选出的单子高度重叠，非独立检验。**
- 留一 trader **四次皆正**：剔 GPT +0.699(p=0.021) / 剔 claude +0.281(p=0.069) /
  剔 Claude-R +0.772(p=0.002) / 剔 BN +0.620(p=0.005)。

## 未消除的核心疑点
**参数随窗口漂移**：赢下 6 天窗口的 lb=2/n=3 在 7 月只有 +1.23(p=0.33)；赢下 7 月的 lb=3/n=3 才是高原中心。
支持该闸门的全部证据 = 单月 + 单组参数 + 收益集中于一个 trader。
