## max_hold 安慰剂：为什么 +5.49 不算

6×5 格点（含曾实盘的 18h 与默认外的 48/72h）：小时轴**非单调**（12h 最差 -5.76、36h 峰 +5.49、
**72h 归零 = 等于 horizon 不触发**，这条是内部一致性校验通过）；豁免轴 ex0% 一致最差 →
做功的是**利润豁免**不是时长。

但基线 **-6.20 是负账本**（实际 +2.37；差异来自 `-horizon 72` 让仓位跑满而非在实盘出场点截断，
且 311 笔里 195 笔是引擎复现不了的 `ai_close`/`market_close`）。`equity-circuit-breaker-backtest.md`
已记死：**在亏损账本上任意截断都倾向改善盈亏**。

安慰剂设计（新增 `Entry.MaxHoldHoursOverride` + `FormatMaxHoldPlacebo`）：**保留豁免条件字节不变、
只逐笔随机化 H**。若直接「随机时点无条件砍」会同时改「何时砍」和「砍谁」，差异无法归因 ——
这正是 equity-breaker 首轮「安慰剂全跑 arm=0」的坑。

⚠️ **频率必须对齐**：首版 H~U[0.25,1.75]×36h 匹配了均值但**开火 45.9 次 vs 真实 32 次**（小 H 在固定
horizon 内更易触发），p=0.2975；收窄到 [0.6,1.4]× 后**开火 31.9 vs 32**，**p=0.4750**、安慰剂均值
+5.04 对真实 +5.49、中位 +5.22 = 掷硬币。**宽区间反而低估了无信息程度。**

## DD 档位：唯一存活的方向，但仍不建议改

`managed_drawdown` 是 GPT 每笔收益最高的机制（+2.21/笔）。扫 arm × giveback：

|---|---|---|---|---|---|---|---|---|

| arm2.5/gb0.8 | +0.72 | 5 | +0.27 | -0.21 | +0.94 | — | 92.8% | 是 |

正面：两轴单调（gb 越紧越好、arm 越早越好）、时间半分双正、三分全正、剔最大仍正、
**胜率恒定 66.2% 而回撤同时改善 25.70→23.05**（不是卖右尾买胜率）。

**但四条反对同等重要**：
1. **效应量 +2.65（占基线 51%）落在引擎 -25.9% 保真误差带内。**
2. **只改动 17/311 笔，且这 17 笔在基线下全部已是盈利单**（+0.22~+1.76），亏损单一笔未动
   （亏损单到不了 arm 阈值）→ 实质是「在已赚单上更早锁一部分利润」，13 改善/4 变差，
   单笔幅度全在 ±0.45 内。
3. **效应 2/3 挤在最后一个三分段**（前半仅 +0.03）。
4. **跨 trader 方向一致但最优点不同**：GPT arm0.9/gb0.8、claude **arm1.5/gb0.8 (+4.78)**、
   Claude-R arm0.9/gb0.3 (+1.64) → 与 `equity-circuit-breaker` staircase 那条「四者无共同值、
   不可跨 trader 迁移」同形态。

## ⚠️ gb=0.3 是回放分辨率产物（重要，别再被它骗）

延伸格点后峰值搬到新网格角 `arm0.9/gb0.3 = +6.34`（基线 5.18 翻倍）—— 这正是
`equity-circuit-breaker` 记的「把上限扩到 504/1008 最优就搬家」= **拟合噪声的确证形态**。

**决定性证据是开火率**：实盘 `managed_drawdown` 开火 16/311 = **5.1%**；回放里 gb0.8 改动 **5.5%（吻合）**，
而 **gb0.3 改动 14.1% ≈ 实盘 3 倍**。而 14.1% 还是 1h 粒度下的**低估** —— 引擎 peak 与回撤
**都按 bar 收盘算**（`replay.go:274,322` 用 `bar.Close`，故无 bar 内前视），只能在 1h 收盘察觉回撤，
而实盘 `poll_interval_seconds=10`。gb=0.3 那 +6.34 依赖「恰好在回放看得见的 44 个收盘时点开火」，
实盘取不到。**claude 上 gb0.3 (+1.35) 差于 gb0.8 (+3.18) 独立印证了这点。**

**推论（可复用）**：任何「紧回撤/紧跟踪」参数都不能在 1h bar 回放上定标，必须先用开火率与实盘对齐，
开火率不同阶就是不同机制。

# 第二轮：以「广谱消灭亏损单」为目标（接受误伤）

第一轮按**净期望**评判；本轮改按**选择性**（消亏$/消赢$）+**广谱性**（覆盖多少已知亏损、跨几个币/周）评判，
误伤只做量化不做否决。结论：**不存在广谱且有选择性的参数**。

## 判据与零假设

- 7 月 311 笔：毛亏 145.27 / 毛赢 147.64 / 净 +2.37。
- **基线选择性 = 145.27/147.64 = 0.9840**。随机拦截 k 笔的期望选择性就是这个数，
  任何过滤器必须**显著高于 0.984** 才含信息量；只看「净改善」会把等比缩表误判成有效。
- **亏损不是尾部驱动**：最大 1 笔占毛亏 5.6%、最大 3 笔 15.6%、最大 10 笔 35.2%、最大 20 笔 52.7%。
  → 不存在「砍尾部」的解；广谱消亏必须打中中位数亏损单，误伤是**结构性的**，不是调参能规避的。

## 选择性随广谱性单调衰减（核心发现）

把 ~50 个候选（conf / net_rr / atr% / 止损距离 / regime / struct / side / lev 各档）按消亏占比分档，
取每档最高选择性：

| 消亏占比档 | 该档最高选择性 | 达成者 |
|---|---|---|
| 5–10% | 4.152 | 止损距离>3.0% |
| 10–20% | 3.057 | net_rr<1.7 |
| 20–35% | 1.289 | atr%<0.8 |
| 35–50% | 1.099 | 止损距离<1.0% |
| 50–70% | 1.073 | side=LONG |
| 70–100% | 1.075 | 止损距离>0.8% |

广谱组（消亏≥50%）n=20 选择性中位 **0.989**；窄谱组（<20%）n=19 中位 **1.418**。
一旦覆盖超过约 35% 的已知亏损，选择性就塌到 1.0–1.1 —— 即按账本原有赢亏比例等比削，等于缩仓。

置换检验（20000 次同样本量随机子集）：

| 候选 | 消亏占比 | 选择性 | p(选择性) | 判定 |
|---|---|---|---|---|
| net_rr<1.7 | 10.7% | 3.057 | **0.0277** | 显著 |
| net_rr<1.8 | 18.0% | 2.152 | **0.0365** | 显著 |
| net_rr>3.0 | 15.3% | 2.049 | 0.0795 | 边缘 |
| atr%<0.8 | 25.9% | 1.289 | 0.1308 | 边缘 |
| 止损距离<1.0% | 49.4% | 1.099 | 0.2469 | ≈随机 |
| side=LONG | 53.1% | 1.073 | 0.2948 | ≈随机 |
| conf<75 | 86.4% | 1.046 | 0.2163 | ≈随机 |
| 止损距离>0.8% | 74.5% | 1.075 | 0.2671 | ≈随机 |

**唯一显著的是 `min_risk_reward`，而它是窄谱的（10–18%），且 1.7 已于 07-31 上线。**

## BE 首档：唯一真正广谱的退出参数，但被 min_eff_pct 机械封死

replay 里 `be1arm-0.3ATR` 消灭 24/105 笔亏损单（22.9%）、零新增亏损单、胜率 66.2%→74.0%，
是唯一有两位数消灭能力的参数。逐层排查后**结论是它不可用**，三个独立原因：

1. **我自己的 sweep 有缺陷**：只改 `TriggerATR` 不动 `OffsetATR`。live 是 arm 1.1 / offset 0.25
   （止损在挂上价**下方 0.85 ATR**）；arm=0.3 而 offset 仍 0.25 只剩 **0.05 ATR** 余量，
   测的是「坏配置」不是「早挂保本」。已补 `be1coup-*` 变体（offset 按 live 比例 0.227 同步缩放）：
   `be1coup-0.3ATR` **-35.46**（vs 未耦合 -13.93），而胜率两者都是 76.9%
   → **胜率由 arm 决定，盈亏由间隙决定**。最优在 `be1coup-0.7ATR` +7.11。
2. **`min_eff_pct: 0.3` 把 offset 顶高**（replay 完全不实现这个 floor）：
   `EffectivePercent`（store/atr_protection.go:45）对**所有** ATR 阈值取 `max(pct, 0.3%)`。
   ATR% 中位 1.011，故 0.25 ATR = 0.253% < 0.3% → **61% 的单子** offset 被顶到 0.297 ATR。
   耦合 arm=0.3 时实际 arm 0.300 / 实际 offset 0.297 → **间隙 0.003 ATR**，挂上即被噪声打掉。
   **BE 首档在机制上无法下移**。逐阈值核查：只有 BE1 offset 被大面积顶高（61%），
   BE1 arm 1%、BE2/dd/ladder/backstop 均 0–3% → 调低 floor 换不来任何自由度，只会放宽 BE1 保护。
3. **1h replay 看不见 BE**：实盘 `break_even_stop` 占 126/311 = **40.5%**，
   两个 replay 基线中 `|pnl|<0.05` 只有 4.2%/6.1% → replay 漏掉该机制 6–10 倍，无权评估 BE 参数。

  **`-liveatr` 目前不应用于结论性回测**，仅作诊断工具。
- **`break_even_stop` 这个 close_reason 不专属于 BE1/BE2 规则**：DD 档位的 `RunnerStopMode=break_even`
  也归到该 reason（当日志计数 dd1 72051 / partial_profit_lock 55967），且 `dynamicOwner` 恒为 `be=0`。
  → 「40.5% 死在保本位」中相当部分来自 DD runner stop，不是 BE 档位。改 BE arm 动不到它们。
- **`exit_price` 是单笔真实成交价，不是多笔均价**：`ladder_sl` 退出中位 **-3.099 ATR**
  对上配置 backstop 3.1 → 可直接用它反解止损位置。
- **实盘 BE 退出位中位 0.648 ATR**（配置 0.25）：BE1 区间（峰 1.1~2.6，n=57）中位 0.648，
  只有 7% 落在 0.20~0.35；BE2 区间（峰 2.6~4.0）中位 1.214 对上配置 1.3。
  BE1 的偏离由 min_eff_pct floor + DD runner stop 混入共同解释。
- **实盘 BE 单 126 笔全部为正**（中位 +0.340）：BE 从不记亏。
- **实盘峰值触发率**（`peak_atr_mult`，194 笔有遥测）：arm 0.3→86.1%、0.5→78.4%、0.7→73.2%、
  0.9→63.4%、**1.1→51.0%**、1.3→43.3%。对照 replay 改动率 0.3→39.9%、0.5→28.3%、0.7→14.8%、0.9→6.8%
  → replay 低估触发 **2.2 倍**。
- **arm=1.1 挂上 99 笔，70 笔（70.7%）死在保本位**，存活 29 笔贡献 +41.48。
- **replay 改动集按实盘峰值分解**（`be1arm-0.3ATR`）：峰 0.3~1.1 档 dPnL **+12.41**（亏单+13.91/赢单-1.50，真实消亏）；
  峰 1.1+ 档 **-17.76**（几乎全赢单，提前挂 BE 把跑单摇下车，真实伤害）；
  峰<0.3 档 -5.46（arm=0.3 在实盘根本不该触发，是 replay 自算 ATR 的伪影）。
- `peak_atr_mult`/`trough_atr_mult` 是**全生命期高低水位、无先后顺序**
  （`UpdateExcursion`，trader/auto_trader_risk.go:4317-4331），`pnlPct` 是**未加杠杆**的价格变动%
  （`calculatePositionPnLPct`），`atrPct = atr/entry*100` → `peak_atr_mult` 与 BE arm 同单位可直接比。
  因缺顺序信息，赢单是否被削无法点估，只能给区间 → 用它做 BE 估计得到的边界过宽（净下界 -22.04/上界 +62.60），
  **不可用于决策**。

## 本轮结论

要「大幅降低已知亏损单」，可选项只有三类，且都不是免费的：

1. **`min_risk_reward` 1.7**（已上线）：唯一统计显著，但只覆盖 10.7% 的已知亏损。
2. **等比缩仓**（`risk_per_trade_pct_of_equity: 6`）：选择性恒等于 0.984，即**纯算术缩放**——
   按比例同时削掉盈亏，降回撤但**不改期望**。这是唯一真正「广谱」的杠杆，代价是收益同比例缩小。
3. **接受不改**：亏损分布无尾部可砍，中位亏损单在开仓时与盈利单不可分（登记过的 AUC≈0.50 上限）。

**未做任何生产配置改动。**
